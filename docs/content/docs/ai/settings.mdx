Modbot's AI features (moderation rules, insights and Chat) all talk to one AI service that you
choose. You set it up once, under **Settings** → **AI** → **Base**, and every feature uses it.

Modbot does not come with an AI service or pay for one. You bring your own: a hosted provider with
your own API key, or a model server you run yourself. Everything AI-related is off until you turn it
on.

Changing anything on the **AI** tab needs the **Change settings** permission
([roles and permissions](/accounts/roles-and-permissions#change-settings)).

## Providers

Modbot talks to any service that understands the OpenAI chat format (often called
"OpenAI-compatible"). The **Connection** card offers these presets:

| Preset | Endpoint it fills in |
|---|---|
| **OpenRouter** (recommended, and the default) | `https://openrouter.ai/api/v1` |
| **xAI** | `https://api.x.ai/v1` |
| **Anthropic** | `https://api.anthropic.com/v1/` |
| **OpenAI** | `https://api.openai.com/v1` |
| **Custom** | Nothing. You type the address. |

A preset only fills in the **Endpoint** box. You can edit the address afterwards.

**OpenRouter is the one we recommend**, and a new Modbot starts on it. One key reaches almost every
model there is, which is why Modbot can show you the whole list with prices (see
[Choosing a model](#choosing-a-model)) and why it knows what each request cost. Nothing stops you
using another provider, and a Modbot that has already saved one keeps it.

Choose **Custom** for anything else, including a model server on your own machine or network, such
as Ollama (`http://localhost:11434/v1`). **Custom** is the only preset that accepts a plain `http://`
address, and the only one that can be switched on without an API key, because a local server
usually needs neither.

<Callout type="info" title="Keeping member data in-house">
If you do not want profile text, Discord messages or moderation history to leave your own servers,
use **Custom** with a model you run yourself. See [What is sent to the provider](#what-is-sent-to-the-provider).
</Callout>

## Setting it up

<Steps>
<Step>

### Open the Base tab

Go to **Settings** → **AI** → **Base**. The card is called **Connection**.

</Step>
<Step>

### Choose a provider

Click one of the provider buttons. The **Endpoint** box fills in.

</Step>
<Step>

### Enter your API key

Paste the key from your provider into **API key**. Leave it empty for a local server that needs no
key.

</Step>
<Step>

### Choose a model

Press **Choose** beside **Model** and pick one from the list, or type a model name yourself. See
[Choosing a model](#choosing-a-model) below.

</Step>
<Step>

### Test

Press **Test**. Modbot sends one short message ("Reply with the single word OK.") and shows either
the model's name with its answer (for example `answered: OK`), or the provider's error in its own
words.

</Step>
<Step>

### Turn it on and save

Switch **AI on** and press **Save**.

</Step>
</Steps>

## The fields

**AI on** is the switch for every AI feature at once. With it off, nothing is sent to any provider,
whatever the other AI tabs say. With it off you can still save an unfinished form, so you can fill
in the endpoint today and the key later. With it on, Modbot will not save until the endpoint, the
model and (for any preset except **Custom**) the key are all there.

**Endpoint** is the full address of the service, starting with `https://` (or `http://` for
**Custom**). It cannot contain `?` or `#`, and it cannot contain a user name or password: put the key
in the key field.

**API key** is write-only. Once saved, the page never shows it again; the label changes to
**API key (stored)** so you know one is there. To replace it, type a new one and save. To delete it,
press **Remove key**.

<Callout type="warn" title="Changing the endpoint forgets the key">
A stored key is only ever sent to the endpoint it was saved with. If you change the endpoint and
save without typing a key, the stored key is removed. The same rule applies to **Test** and the
model list: against a different address, they go without the stored key. This stops a key being
redirected to another server.
</Callout>

**Model** is the model every feature uses unless you choose another one for it.
[Insights](/ai/insights) and [Chat](/ai/chat) each have their own **Model** box; left empty, they use
this one.

## Choosing a model

Every **Model** box has a **Choose** button. What it opens depends on your provider.

### On OpenRouter

You get OpenRouter's whole list, as Modbot last fetched it, with:

| Column | What it is |
|---|---|
| **Model** | The model's name, its id underneath, and chips for what it can do |
| **Maker** | Who makes it — the part of the id before the `/` |
| **Input $/1M** | US dollars per million tokens you send |
| **Output $/1M** | US dollars per million tokens it writes back |
| **Cached $/1M** | What input the provider already has cached costs instead |
| **Context** | How much a request and its answer can hold together, such as "200K" |
| **Per 1,000 calls** | What a thousand calls would cost *you* — see below |

Search by name or id, filter by maker, by **Tools**, by **Structured output**, by **Free**, or by a
highest price per million; sort by any column. Click a row to choose that model.

The chips are the short version of what a model can do: **Tools**, **Structured output**,
**Images in**, **Free**. Where a model cannot do something the feature needs, the chip says so
instead — **No tools** on a model Chat could not use, **No structured output** on one moderation
rules could not use — and a router whose price depends on the model it picks shows **Price varies**.

**The order.** Models recommended for the box you opened come first, cheapest first. A model is
recommended when it can do what that feature needs (tools for Chat, structured output for moderation
rules, nothing in particular for insights, which are written as plain text, and both for the **Base**
box that everything falls back to), when it has a real price, and when OpenRouter added it less than
eighteen months ago. Modbot never favours a particular
model by name.

**Per 1,000 calls** appears once Modbot has AI usage of its own to work from: it takes the average
request that feature has actually made over the last thirty days — input, cached input and output
tokens — and prices a thousand of them on each model, using the same sums as
[Limits and spend](/ai/limits-and-spend). With no usage yet, the column is not shown.

**Fetched** in the corner says how old the list is; **Refresh** fetches it again from OpenRouter,
which is the same fetch the **Limits** tab's **Fetch prices** button makes. Modbot fetches on its own
once a day while AI is on and set to OpenRouter.

### On any other provider

Modbot asks your endpoint for its own list of models and shows it, with the price beside any model
you entered a price for on the [Limits](/ai/limits-and-spend) tab, or **No price**.

### A model that is not on the list

You can always type a model id yourself, whatever the list says: the box keeps what you type, and the
picker marks it **Not in list**. Use **Test** to check it works.

## The Test button

**Test** uses the values on the form, not the saved ones, so you can check a new key before it
replaces one that works. It needs an endpoint and a model.

A test is a real request to the provider. It is counted as the **Connection test** feature on the
[Limits](/ai/limits-and-spend) tab, and a spend limit can stop it. If a limit is reached, **Test**
shows that limit's sentence instead of calling the provider.

If the model list does not load, the endpoint may not offer one. That is not an error: type the model
name yourself and use **Test** to check it.

## What is sent to the provider

Everything below goes to the endpoint on **Base**, with your key. Text your members wrote — Discord
messages, VRChat display names, bios, status lines and pronouns — is sent to the AI provider you
choose. Your provider's own terms decide what happens to it there.

The first time you switch **AI on**, Modbot shows you this list and you have to confirm it. That
happens once for the deployment, and it is recorded in the
[audit log](/moderation/audit-log) with your name, the time and the endpoint you were shown.

| Feature | What is sent |
|---|---|
| **Test** | The single message "Reply with the single word OK." |
| Model list | A request for the model list. No group data. |
| [Moderation rules](/ai/moderation-rules) (AI topics only) | Modbot's instructions; the name, "What to catch" text and sensitivity of each AI topic that applies; which kind of text it is (a Discord message, a VRChat display name, bio, status or pronouns); and the text itself, up to 4,000 characters. The person's name and id are not sent. Term lists never send anything. |
| [Insights](/ai/insights) | Modbot's instructions and the insight's figures: counts for the period and the period before, and short lists of the busiest worlds and rooms by world name. No person's name, id or messages. |
| [Chat](/ai/chat) | Modbot's instructions (including the group's name, the current time and any extra instructions you wrote), the whole conversation so far, the list of tools on offer, and every tool result. Tool results are Modbot data: names, bios, ban history, audit log entries, who is in a room. The asker's Modbot account id is not sent. |

AI requests go out on their own connection. They never use the proxy you may have set up for
VRChat.
