Modbot runs as **one service plus one PostgreSQL database**. There is no Redis, no search server, no
message queue and no outside sign-in service to set up.

The service needs one setting to start: `DATABASE_URL`, which tells it where the database is.
Everything else, from the VRChat account to the Discord bot, is entered in the web app through the
[setup wizard](/setup-wizard) and **Settings**, and stored in the database.

## What is required

### The Modbot server

One container, built from the `Dockerfile` at the root of the repository. It holds:

- the web app your staff open in a browser,
- the API,
- the VRChat sync, which reads your group's audit log, members, bans and profiles,
- the Discord bot, which only starts once you give it a token.

Run **exactly one copy**. Modbot signs in to VRChat with one account and paces its requests to
stay inside VRChat's rate limits. A second copy would send twice as many requests against the same
limit, and neither copy could see what the other was doing.

The server listens on the port in `PORT` (8080 if you do not set one) and answers two health checks,
`/health/live` and `/health/ready`. See [Checking a deployment](/self-hosting/health).

### PostgreSQL

The database holds everything: settings, staff accounts, the history Modbot records, and the keys
Modbot uses to protect stored passwords and keep people signed in. Modbot creates and updates its
own tables every time it starts. See [PostgreSQL](/self-hosting/postgres).

## What is optional

| | What it is for | Where you set it up |
|---|---|---|
| **Evidence storage** | Keeping screenshots and videos attached to case files. You can use an S3-compatible storage bucket, a folder on disk, or the database itself. Until you choose one, uploads are turned off and everything else works. | **Settings**, **Evidence** tab. See [Storage buckets](/self-hosting/storage-buckets). |
| **The Discord bot** | Posting events to Discord, instance announcements, account linking, and reading your Discord server. | The setup wizard, or **Settings**, **Discord** tab. See [Setting up the bot](/discord/bot-setup). |
| **Email (SMTP)** | Sending email, such as password reset links. | The setup wizard, or **Settings**, **Integrations** tab. |
| **An AI provider** | AI moderation rules, insights and chat. | **Settings**, **AI** tab. See [AI settings](/ai/settings). |
| **A proxy** | Reaching VRChat from a host whose network VRChat's Cloudflare protection blocks. Common on VPS and datacentre hosting. | The setup wizard's connection check, or **Settings**, **VRChat Service Account** tab. |
| **Seq** | Sending logs to a [Seq](https://datalust.co/seq) server, so you keep them when the container's disk does not survive. | The `SEQ_URL` environment variable. |

A Modbot with none of these is complete and working: it syncs your group, and your staff can use
every page that does not depend on one of them.

## The project's central services

The Modbot project runs a few services of its own. A self-hosted Modbot does not need any of them to
sync your group or run your moderation. Here is what each one is used for.

### my.modbot.co

A page that remembers the Modbot addresses you use, so you can pick one from a list instead of
hunting for a URL.

- When you finish the setup wizard for the first time, Modbot opens
  `https://my.modbot.co/register?url=` followed by your Modbot's address, in a new tab. That page
  saves the address in your browser. my.modbot.co also records that the address was registered; if
  it cannot right then, the page says **Saved on this device** and sends the address later, while
  the tab is open or the next time you open the page.
- **Your account** in the web app has an **Add to my.modbot.co** button that does the same thing
  later.
- The companion's pairing button opens `https://my.modbot.co/go?redir=/pair`, which lists your
  saved Modbots and sends you to the pairing page on the one you pick. See [Pairing](/companion/pairing).
- AI moderation can use shared term lists published on my.modbot.co. Modbot fetches a list only if
  you choose to use one. See [Moderation rules](/ai/moderation-rules).

If you would rather not use it, skip the tab it opens and bookmark your Modbot's address instead.

### Modbot Cloud

`cloud.modbot.co` keeps a backup of what companions read from VRChat's log: presence events
for every instance their moderator is in, never raw log lines. Each client sends this straight to
Modbot Cloud, whether or not it is paired, unless the person using that PC turns it off in the
client's own settings. Your Modbot server has no say in it. See
[Client settings](/companion/settings#modbot-cloud-backup).

Your Modbot server's own `MODBOT_CLOUD_ENDPOINT` and `MODBOT_CLOUD_DISABLED` are only about your
server: which Modbot Cloud it talks to, and whether it talks to one at all. See
[Environment variables](/self-hosting/environment-variables).

Your server uses Modbot Cloud for three things:

- **The term lists.** **Settings → AI → Moderation** downloads them from there.
- **Open instances.** Which of your group's instances anyone can join, so they can be listed on modbot.co.
  See [Open instances](/self-hosting/open-instances).
- **A report every six hours**: your server's address, its version, the operating system it runs on,
  your VRChat group's id, name, description, icon and banner, whether Discord is connected, which
  term lists you imported, how many rate-limit cold stops and WAF blocks there have been, and
  whether AI moderation is on.

**Never how many people anything has.** There is no field in the report for the number of users, the
number of group members, or the number of people in a VRChat instance, and none for any member, any
moderation record, any credential or any log line.

Set `MODBOT_CLOUD_DISABLED=1` and none of it happens.

One thing it does not stop: **checking for a newer Modbot release**. That question sends nothing
about your deployment — no id, no group, no version — and everyone gets the same answer, so it is
not one of the things that variable is protecting you from. The **Check for updates** switch under
**Settings**, **Host & Database** is what turns it off, and it is on by default. Modbot never
updates itself. See [Updating](/self-hosting/updating#how-you-find-out-there-is-one).

**Settings → Data → Modbot Cloud** shows when the last report went and gives you a link code, which
you type into `cloud.modbot.co` to claim this server on your Cloud account. The code lasts 15
minutes and works once. **Health** shows the last report too.
