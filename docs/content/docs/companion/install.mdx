---
title: Installing the companion
description: Download and install the Modbot companion on Windows, keep it up to date, and see exactly what it reads and sends.
---

The Modbot companion is a small Windows program for moderators. It reads VRChat's own log
file on your PC, works out which instance you are in and who comes and goes, and tells your
group's Modbot. That is what fills the [Live](/moderation/live) page and each person's presence
history. It sits in the tray (the icons near the clock) for as long as it runs.

## What you need

- **64-bit Windows 10 or 11.** The client is built for Windows only. There is no Mac, Linux or
  Quest version.
- **VRChat for Windows, on the same PC.** The client reads the log that VRChat writes on that PC.
- **Nothing else installed first.** The client brings its own copy of .NET.
- **No administrator rights.** It installs into your own user folder and only changes settings
  for your own Windows account.
- **SteamVR**, only if you want the [overlay](/companion/overlay). Without SteamVR the client
  still reports presence as normal.
- **A staff account on your group's Modbot**, to [pair](/companion/pairing) the client with
  it. Until you pair, the client reports to no group server.

## Download

Releases are published on the Modbot repository's
[GitHub Releases page](https://github.com/binn/Modbot/releases). Each release has these files:

| File | What it is |
|---|---|
| `Modbot-win-Setup.exe` | The installer. Use this one. |
| `Modbot-win-Portable.zip` | The same program with no installer. Unzip it anywhere and run `Modbot.exe`. |
| `Modbot-…-full.nupkg`, `…-delta.nupkg`, `releases.win.json`, `RELEASES` | What installed clients download when they update. You never need these. |

## Install

<Steps>
<Step>
### Run the installer

Run `Modbot-win-Setup.exe`. There are no questions. It installs to
`%LOCALAPPDATA%\Modbot`, adds **Modbot** to the Start Menu and to Windows' list of installed apps,
and opens the client.
</Step>
<Step>
### Get past SmartScreen if Windows asks

If a blue **Windows protected your PC** box appears, press **More info**, then **Run anyway**. Some
browsers also ask whether to keep the download: keep it. See the note below.
</Step>
<Step>
### Pair it with your group's Modbot

The client opens on its **Servers** page. Follow [Pairing](/companion/pairing) to connect it
to your group.
</Step>
</Steps>

<Callout type="warn" title="Unsigned builds and SmartScreen">
A release is only code-signed when the project has a signing certificate set up. Without one, the
build is unsigned, and Windows SmartScreen warns about it because it has no publisher to check.
The warning is about the file being new and unsigned, not about anything the file does.

Windows Defender may also, now and then, hold back an unsigned program that reads another
program's files and uses the network, which is what this client does. If Modbot disappears right
after installing, look in **Windows Security → Protection history**.
</Callout>

## The client window

Closing the window does not stop the client. It keeps reading and reporting from the tray. Click
the tray icon, or choose **Open Modbot** from its menu, to bring the window back. **Quit — stops
reporting** in the tray menu really does stop it: the log stops being read at once.

Only one copy runs per Windows account. Opening Modbot again while it is already running just
brings up the window.

The window has four pages:

| Page | What it shows |
|---|---|
| **Servers** | Each paired server, whether it is reporting, and the pairing controls. See [Pairing](/companion/pairing). |
| **Events** | Every event the client has handled, newest first — one line each, with where it went (the paired server, Modbot Cloud, both or neither) and whether it was **sent**, **waiting**, **withheld** or **failed** there. Events held back, for example while paused, are listed too, along with notes such as "Paused" or "Resumed reporting". It shows the latest 200 events and keeps 1,500 lines on disk. |
| **Log** | What the client makes of VRChat's log: **lines seen**, **lines Modbot looks at** and **recognised**. You can open the same file in Notepad and check the counts. |
| **Settings** | The client's switches. See [Client settings](/companion/settings). |

The line at the bottom of the sidebar says **reading VRChat's log**, **VRChat not running**, or
**log not recognised**.

### Warnings in the window

Warnings show at the top of every page.

| Warning starts with | What it means | What to do |
|---|---|---|
| *VRChat is running and writing to its log, but Modbot has not recognised anything in it recently.* | VRChat's log has had new lines for 10 minutes and none of them matched anything the client understands. The client names two causes: VRChat was started without its verbose logging options, or VRChat changed its log format. | Check how VRChat is started. If that is not it, update the client. Nothing is recorded until this is fixed. |
| *Reading VRChat's log failed: …* | The client hit an error while reading. After five failures in a row the reader stops until you restart the client. | Send the client's log file (see [where things are](#where-the-client-keeps-its-files)) to whoever looks after your Modbot. |
| *The saved credential for "…" cannot be decrypted on this Windows account.* | The pairings file was copied from another Windows account or PC. Saved tokens only work for the account that saved them. | Pair that server again. |
| *"…" rejected this device.* | That server refused the client's token, usually because an operator revoked it. | See [When a token is revoked](/companion/pairing#when-a-token-is-revoked). |
| *"…" has been upgraded past what this client can speak to.* | The server is newer than this client supports. Events are still queued. | Update the client. |
| *Modbot … has been downloaded and will be installed the next time Modbot starts.* | An update is ready. | Quit from the tray and open Modbot again whenever it suits you. |

If something in the client crashes, Windows shows a **Modbot ran into a problem** box (the client
keeps running) or a **Modbot has stopped** box (it closed). Both name the folder with the client's
log.

## What the client reads, and what it sends

### What it reads

One folder: VRChat's log folder. On Windows that is `%USERPROFILE%\AppData\LocalLow\VRChat\VRChat`.
On Linux, VRChat runs under Proton and the same folder sits inside the Proton prefix in your Steam
library, `steamapps/compatdata/438100/pfx/drive_c/users/steamuser/AppData/LocalLow/VRChat/VRChat`;
the companion looks for it under `~/.local/share/Steam`, `~/.steam/steam`, the Flatpak and Snap
Steam folders, and last a plain Wine prefix under `~/.wine`. A library somewhere else is set under
**Settings**, **VRChat log folder**. Inside the folder, only the files VRChat names
`output_log_*.txt`, and only the newest one. The client opens the file to
read while VRChat is still writing it, never changes it, and makes no copy.

Of all the lines in that file, the client only looks at lines VRChat tags `[Behaviour]`, and inside
those it recognises a handful of shapes:

- you joining an instance (which world and instance),
- which display name is yours,
- someone joining or leaving, with their display name and VRChat user id,
- someone switching avatar (VRChat logs the avatar's name, never its id).

Everything else is skipped. Lines that were already in the file when the client started are read
only to work out which instance you are in. They are never reported.

It does not read chat, your friends list, the screen, your screenshots folder, the clipboard, the
keyboard or which other programs are running. It does not read Steam's settings. It has no way to
attach files to a case: you do that in the web app, by choosing a file.

### What it sends to your group's Modbot

From what it recognises, the client builds five kinds of event:

| Event | Meaning |
|---|---|
| Joined | Someone arrived while you were already in the instance. |
| Already there | Someone was in the instance when you arrived. |
| Left | Someone left. |
| Changed avatar | Someone switched avatar. Carries the avatar's name. |
| Log stopped | VRChat's log stopped growing for about two minutes while you were in an instance. Names you, and is sent once per stop. |

Each event carries a random event id, its type, the time it happened (adjusted to the server's
clock), the person's VRChat user id and display name, the world id, the instance id and the group
that owns the instance. The instance id never includes the secret part of an instance's address
that would let someone join it.

A server only ever gets events for **its own group's instances**. The group is written inside
VRChat's instance address, so the client decides this on your PC with no lookup. Public,
friends-only and private instances, and other groups' instances, are never sent to any Modbot
server. If you moderate two groups, neither group's server hears about the other's instances.

Events go over HTTPS (plain HTTP is only allowed to your own PC, for testing). Someone arriving or
leaving is sent within about two seconds. Otherwise the client sends every 30 seconds or when 50
events are waiting. If the server cannot be reached, events wait on disk (up to 50,000 per server,
for up to three days) and go out when it is back.

The client also talks to a paired server in these ways:

- It asks the server's time soon after it starts or pairs, and every two hours after that, so its
  timestamps line up with the server's clock.
- While you are in that group's instance, the [overlay](/companion/overlay) asks for the
  instance's roster (which tells the server the instance id) and waits for flagged-user alerts.

Everything the client sent to a server is listed on **Events**.

### What it sends to Modbot Cloud

Unless you turn it off, the client also sends **the same events, for every instance you are in**,
straight to Modbot Cloud (`https://cloud.modbot.co`) as a backup. That includes public,
friends-only and private instances, where the group is left empty. It works the same before and
after you pair, and a paired server has no say in it. It never sends VRChat's raw log, and never
the secret part of an instance's address.

What went to Modbot Cloud is listed on **Events**, beside the same event's line for a paired
server. How the backup works, and how to turn it off in the
client's settings file or with environment variables, is on
[Client settings](/companion/settings#modbot-cloud-backup).

### Other connections

- **Updates.** An installed client asks the release feed on GitHub whether there is a newer
  version, and downloads it if so. The request does not identify you or your install.
- **Pairing.** Pressing **Pair with a server** opens a page in your browser. The client itself only
  contacts the server named in the pairing link. See [Pairing](/companion/pairing).

The client does not upload its own log file anywhere.

## Updates

An installed client (from `Modbot-win-Setup.exe` or the portable zip) checks for a newer version
30 seconds after it starts and every four hours after that. A newer version downloads in the
background, and the window shows a line saying it will be installed the next time Modbot starts.

Nothing is installed while Modbot is running, so an update never cuts a VRChat session short. Quit
from the tray and open Modbot again whenever it suits you. The update is installed before the
window opens, and the client comes back up. Your pairings and settings are kept: updates never
touch `%APPDATA%\Modbot`.

If a check fails (no connection, or the release feed cannot be read), the client writes
`Could not check for updates` to its log and tries again four hours later. You can always download
the latest `Modbot-win-Setup.exe` and run it over your current install.

To stop the client checking at all, see
[Check for updates](/companion/settings#check-for-updates).

A copy you built yourself, or ran from a folder you copied, is not an installed copy and never
checks for updates.

## Where the client keeps its files

| What | Where |
|---|---|
| The program | `%LOCALAPPDATA%\Modbot`. The portable zip runs from wherever you unzipped it. |
| A downloaded update waiting to be installed | `%LOCALAPPDATA%\Modbot\packages` |
| Paired servers and their tokens (tokens encrypted to your Windows account) | `%APPDATA%\Modbot\pairings.json` |
| Settings | `%APPDATA%\Modbot\settings.json` |
| Events waiting to go to each server | `%APPDATA%\Modbot\queue` |
| The **Events** list | `%APPDATA%\Modbot\sent.jsonl` |
| The client's own log, one file a day, last seven kept | `%APPDATA%\Modbot\logs` (`client-YYYYMMDD.log`) |
| Events waiting to go to Modbot Cloud (up to 20 MB) | `%APPDATA%\Modbot\cloud` |
| The client's Modbot Cloud install id (secret encrypted) | `%APPDATA%\Modbot\cloud-installs.json` |

The client also writes two things to the registry, both under your own account and neither needing
administrator rights:

- `HKEY_CURRENT_USER\Software\Classes\modbot-companion`, so pairing links from your browser open the
  client.
- A value named `Modbot` under
  `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`, so an installed copy starts
  when you sign in. See [Start with Windows](/companion/settings#start-modbot-companion-when-my-computer-starts).

The client's log is the first thing to send when you report a problem. Paste `%APPDATA%\Modbot\logs`
into File Explorer's address bar to open the folder. The first line of each run says which version
started.

## Uninstall

Go to **Settings → Apps → Installed apps → Modbot → Uninstall** in Windows. That removes the
program, its Start Menu entry and the start-with-Windows entry.

It leaves `%APPDATA%\Modbot` (pairings, settings, queues, the sent list and the logs), so a
reinstall picks up where you left off. Delete that folder to remove everything. The
`modbot-companion` registry key is also left behind. It points at a program that is no longer there,
which does no harm, and you can delete it at any time.

Uninstalling does not tell your group's server. The token simply stops being used. An operator
can also [revoke it](/companion/pairing#paired-devices-on-the-server).

## Building it yourself

If you would rather not run a downloaded program, build the same folder the installer contains
from the source, with the .NET 10 SDK:

```bash
dotnet publish src/Modbot.Companion.App -c Release -p:PublishProfile=win-x64
```

The output is in `artifacts/client/publish`. Run `Modbot.exe` from there. A copy built this way
does not check for updates and does not show the start-with-Windows switch.
